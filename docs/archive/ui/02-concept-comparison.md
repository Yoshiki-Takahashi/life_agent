# LifeAgent UI刷新: 5構想と比較評価

> 履歴資料です。現在の実装仕様は[仕様の入口](../../README.md)を参照してください。

参照: [理念・UC](01-principles-and-use-cases.md)。
評価主体はCodex。画面構成と操作の机上評価であり、利用者テストの結果ではない。
5案は配色違いではなく、最初に見る情報と移動の仕方を変える。

## A. Goalワークスペース
- 中心: 選んだ目標を「概要・進み具合・計画」に整理。記録は常設ボタン、振り返りは進み具合から。
- 起点: シンプルな目標一覧。目標を開いた後は同じGoalの文脈を維持。
- 可視化: 指標を選び、累積と目標、根拠記録を一続きに確認。
- 強み: 記録・数値・計画変更を迷わず行き来でき、既存データ構造に合う。
- 弱み: 複数Goalにまとめて記録するには切替が必要。タブの役割を教える必要がある。
- 見た目: 静かな面、濃い見出し、余白、ティールの主操作。情報は必要な場所で展開。
- 主経路: 一覧→Goal概要→常設「記録する」→確認→保存結果。

## B. 今日の一歩
- 中心: 今日記録したい目標と最近開いた目標。毎日の入口を短くする。
- 起点: 最近使ったGoalから本人が選ぶ。AIによる優先順位は付けない。
- 可視化: 保存後に小さな変化を表示。詳しいグラフはGoalへ移動。
- 強み: 短時間の記録、空白からの再開に向く。
- 弱み: 期限と中長期計画が奥に入りやすい。「今日のタスク」を自動生成するには追加仕様が必要。
- 見た目: 大きな記録入口と短いカード、日付を起点とする軽いレイアウト。
- 主経路: 今日→Goal選択→記録→保存。

## C. インサイトノート
- 中心: 数字と振り返り。指標の期間推移から記録を掘り下げる。
- 起点: Goalと指標を選択した可視化ページ。
- 可視化: グラフ、期間実績、元記録を同じ流れで読む。
- 強み: 進捗把握・週次レビューに強い。グラフから実績の根拠へ到達しやすい。
- 弱み: 初回・記録なしで価値を感じにくい。毎日の入力が分析画面の脇になる。
- 見た目: 編集されたレポート、明瞭な軸と単位、数値より意味の見出し。
- 主経路: Goal選択→グラフ→期間→記録詳細→次の行動。

## D. 対話コーチ
- 中心: 自然文を入口に、計画・記録・助言を会話と構造化カードで進める。
- 起点: 対象Goalを指定した対話。
- 可視化: 必要時にグラフカードを呼び出す。
- 強み: 曖昧な目標・入力開始が自然。問いかけで躓きを拾える。
- 弱み: 保存済み状態が会話に埋もれる。現在のAPIには会話履歴・自由相談がなく追加開発が大きい。
- 見た目: 余白のある会話、候補を囲む確認カード、対象Goalを常時表示。
- 主経路: Goal指定→発話→候補カード→確認保存。発話だけでは保存しない。

## E. マイルストーンの道のり
- 中心: 目標から中間目標への道筋。今の位置と次の節目を視覚的に追う。
- 起点: Goalの期限付きMilestoneを時系列表示。
- 可視化: 全体の道のり＋選択したMetricの詳細。
- 強み: 初期計画の理解、計画の変更前後の比較に強い。
- 弱み: 現行Milestoneには完了状態がない。「ここまで達成」の表現は追加契約なしでは使えない。
- 見た目: 縦の道のり、日付と短い節目、控えめな達成表現。
- 主経路: 道のり→指標→記録。節目の期限だけで完了扱いにしない。

## UCごとの適合度

1=構造上実施しづらい。点数は仮説であり、秒数・成功率の測定結果ではない。

## 共通シナリオの机上ウォークスルー

| 案 | S1 読書の今回+1記録 | S2 開発の異種指標 | S3 筋トレの負担への配慮 | S4 再開・S5 見直し |
| --- | --- | --- | --- | --- |
| A | 常設記録→候補→保存で文脈維持 | 指標切替で画面とテストを分離 | 保存結果の助言を主操作から分離 | 概要→計画→差分。未記録を中立表示 |
| B | 最短の入口を作りやすい | 複数Goal・指標の切替が増える | 今日の達成を強調しすぎない設計が必要 | 再開に強いが中長期の変更は別画面 |
| C | 入力を見つける前にグラフがある | 指標を並べず個別に読める | 運動量グラフの増加を善としない必要 | 振り返りは容易、見直しへ移動が必要 |
| D | 自然文は容易、保存確認が必須 | 同単位の指標をカードで明示する必要 | 対話は文脈を扱えるがAI品質への依存大 | 過去会話と最新の正本が紛れやすい |
| E | 記録対象の節目選択が余分になり得る | MilestoneとMetricの関係を誤解しやすい | 完了・未達の演出が圧迫になり得る | 計画理解に強いが現在位置を自動判定できない |

S6の障害時は全案で「進捗保存」と「助言取得」を独立表示する必要がある。
UI構想の点数が高くても、無断保存・無断計画変更・不明な率の表示は失格とする。

## 選定結果と判断の範囲

**2026-10-25、利用者がD「対話コーチ」を採用した。**
「対話コーチの案を採用してください」という明示の選定に基づく。
[採用案のUI設計書](03-conversation-coach-design.md)を以後の設計基準とする。

比較時の推奨はAだった。記録・進捗把握の両立と既存APIへの適合を評価したもので、
その判断と採点は履歴として維持する。利用者の採用後に点数を変更しない。
Dの正本状態の分かりにくさ、通知設定の発見性、追加APIの必要性は弱点として残す。

採用設計では、対象Goalと最新実績を固定し、構造化カードで確認保存、
参照画面で可視化、共通設定で通知を扱う。
初期版は既存APIによる目的別の対話、自由相談と会話永続化は後続として区別する。
対話中心の構造を保ち、Goalワークスペースへ置き換えない。
構想の採用と実装完了は別で、現段階では設計書を作成した状態。

## 採用を検証する方法

読書・開発・筋トレの各題材でU1〜U8を実行し、利用者が操作場所と保存状態を説明できるか確認する。
目安は記録入力への到達2タップ以内（一覧から）、確認保存の誤認0件、
グラフの現在値・目標・期間の説明、差分適用前の変更内容説明。
これは今後の受け入れ目標であり、検証済み数値ではない。
Dについては特に「未保存を保存済みと誤認しないこと」「過去の会話を読まず現在値を説明できること」
を検証する。Goal切替や計画理解に課題が出た場合も、まず採用案の導線を改善し、その効果を評価する。
