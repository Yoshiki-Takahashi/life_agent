# Weekend 10: 定期振り返りと通知

## User Story
ユーザーとして期間内の実績を振り返り、希望した頻度で振り返りを促してほしい。

## 実装・受け入れ条件
- Goal詳細から「振り返り・通知設定」を開き、直近7日／30日の記録と助言を表示する。
- 選択タイムゾーンで今日を含む暦日を対象とし、未来・不正日時を除外する。
- 助言は期間内の記録有無に基づく固定文。AI要約・新しいAI呼出しは追加しない。
- 通知は初期無効。端末内・ユーザー別に有効化、毎日／毎週日曜、IANAタイムゾーンを保存する。
- 20時頃の端末内inexact AlarmManagerを採用。省電力等による遅延を画面へ明記。
- POST_NOTIFICATIONS拒否でも手動利用可能。設定保存時のみ権限を要求する。
- 同一ユーザー・同一現地日の通知を永続キーで抑止。通知IDも固定し二重表示を防止。
- 無効化・ログアウトで予約と表示中通知を取消。通知本文にGoalや進捗を含めない。
- 再起動・端末時刻変更で再予約。タイムゾーン設定は明示値を維持する。
- 通知タップでアプリのGoal一覧へ戻り、Goalを選んで振り返る。

## 責務・採否
既存APIで保存済み履歴を取得し、Androidで期間の表示対象を選ぶ。
正本保存と所有者認可はCore APIのまま。端末のない状態での配信は要件にないため
Cloud Scheduler・サーバー定期処理は不採用。複数端末間の設定同期・集中配信が
必要になった場合に再検討する。新しいクラウドリソース・DB/API契約変更なし。

## 完了条件
単体テスト・lint・ビルド、クラウド接続Emulatorでの画面確認、運用文書更新。

## 対象外
厳密な時刻保証、通知設定の端末間同期、AI期間要約、自動計画変更。

## 次回の最初の作業
実際の定刻通知を端末の省電力状態も含めて運用確認する。

## 検証結果（2026-10-25）
- 最新mainのWeekend 8再計画を取り込み、既存の再計画操作を維持。
- Cloud Firebase設定で単体テスト・lint・APK作成・Pixel_8へのインストール成功。
- ReviewScreenTest: 7日/30日切替、記録なし、通知権限に依存しない手動利用、不正タイムゾーンの拒否を確認。
- ReviewReminderTest: 通知権限拒否、許可後の通知生成、同日重複抑止、無効化・ログアウト時の停止を確認。
- 通常のクラウド接続アプリを再インストール・起動済み。instrumentation後は再ログインが必要。
- 実際の定刻・省電力・端末再起動を跨ぐ通知の運用確認は残件。
