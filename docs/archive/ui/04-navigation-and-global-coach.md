# UI仕様改訂: 共通メニューと全目標コーチ

> 履歴資料です。現在の実装仕様は[仕様の入口](../../README.md)を参照してください。

日付: 2026-10-31。利用者フィードバックに基づく採用仕様。
本書は03設計書の「Goalごとの対話」「コーチ・目標・設定」「Goal詳細の縦一列」に優先する。

## 変更
1. 認証後の全画面に下部メニュー「目標一覧・新規作成・コーチ」を常設する。
   詳細・計画確認・進捗確認・振り返りにも表示。キーボード使用時もメニューを残す。
2. コーチはユーザーにつき一つのセッション。全所有Goalの現在値・目標・期限を踏まえて会話する。
   Goal詳細に入ることや対象Goalの事前選択を必須にしない。
3. コーチは対話履歴と入力欄が中心。固定Goalサマリー、目的切替、参照リンクの列は置かない。
   候補の確認・取消などその返答に必要な操作だけを対話カード内へ表示する。
4. Goal詳細は「概要・進捗・記録・計画」のタブで切替。タブバーを固定し、
   一つの長いスクロールでグラフ・入力・再計画を探させない。振り返りは進捗タブから開く。

## 会話と確認
- 読取り専用の全目標対話APIを追加する。Core APIが所有者で絞った全Goalを読み、
  期限と現在のMetricを既存内部AI接続サービスへ渡す。DB transactionはAI待機前に終了。
- 直近12発話を送信し、このセッション内の文脈を扱う。会話DBや端末間同期は追加しない。
- 応答は固定Schema: reply / intent(discuss|record) / goal_id / record_body。
- 記録対象が曖昧なら対話で確認。複数目標の実績は一件ずつ確認する。
- record_bodyは現在または履歴中の利用者発話の原文だけを採用し、AIによる実績文の捏造を拒否。
- 記録時のみ対象Goalを取得し、既存Parser→候補確認→既存保存APIへ渡す。
  確認画面に対象名・今回値・保存後の値を明記。自動保存しない。
- 全目標の相談で自動的に優先順位や計画を確定しない。変更は引き続き差分承認が必要。
- Fakeは全Goalの現在値を返す決定論的な確認用応答。実AIと区別する。実AI接続は既存内部サービスへ集約。

## メニュー遷移と入力
- 主要画面の遷移は共通メニューから行う。同じ項目の連打で画面を積み上げない。
- 入力・候補がある場合は「続ける／破棄して移動」を表示する。
- 保存中・適用中、およびコーチの保存結果未確認ではメニューを表示したまま移動を止め、解決手段を表示する。
- 参照の往復で全目標対話は維持。ログアウト・ユーザー切替で消去。
- 認証画面は保護領域へ遷移できないためメニューを表示しない。
- Debug専用の単独プレビューは確認補助。通常アプリの全画面遷移は実際のローカル認証・APIで確認する。

## 受け入れ条件
- 一覧→新規→コーチ→詳細→タブ→一覧を下部メニューから辿れる。
- 二つ以上の目標を含む会話が可能で、目標切替でスレッドを分割しない。
- 別ユーザーのGoalをAIへ送らず、AIが返す他人・不明なGoal IDを拒否。
- 記録・再計画は明示確認後だけ反映し、移動や再送で二重反映しない。
- コーチ上に恒常的なリンク群やGoal選択フォームがない。
- タブ切替で既存の進捗記録・再計画・グラフを利用できる。
