## 1. 目的と採用判断

**「話して始め、根拠を確かめ、自分で決める。」**

自然文を入口に、コーチの短い案内と操作できるカードで目標管理を進める。
必要なときには数値と計画を直接参照でき、AI候補の保存・変更適用は本人が決める。

机上評価ではAが最高、Dは66.0/100だった。評価を採用結果に合わせて書き換えない。
採用理由として利用者が明示したのは構想名のみで、選択の動機を推測して本人の意見としない。
以下の弱点対策の効果は実装後に検証する。

| 弱点 | 対応 | 検証 |
| --- | --- | --- |
| 最新状態が会話に埋もれる | 対象Goalと最新実績を会話の外に固定 | 読み返さず現在値を説明できる |
| 送信と保存を混同する | 未保存の候補カードと確認保存を独立 | 候補を保存済みと誤認しない |
| グラフや計画が見つけにくい | 常設の参照ボタンから専用画面へ直行 | 発話せず到達できる |
| 通知設定が会話に紛れる | 主ナビゲーションの設定へ分離 | Goal未選択でも変更できる |
| 自由相談APIがない | 初期版は目的を選んで話す対話 | 未対応の質問に架空の回答を出さない |

## 2. 初期版と後続の範囲

### 初期版: 目的別の対話
- 入力目的は「記録する」「計画を見直す」「新しい目標」。参照操作は「進み具合」「振り返る」「計画」。
- 記録・見直しは自然文を既存Parser・Re-plannerへ渡し、候補をカードで確認する。
- 新規目標は本文、任意の補足、期限を会話形式で案内し、既存APIの必須項目を揃える。
- 短い固定ガイドと構造化カードで対話を構成する。すべての吹き出しをAI生成にはしない。
- 自由な意図推定、汎用相談API、新しいAI接続先、会話DBを追加する前提にしない。
- 過去のProgressLogは閲覧可能だが、セッションを跨ぐ発話・助言の履歴とは区別する。

### 後続: 自由相談・継続対話
目標に関する質問の往復、会話履歴の保存・端末間同期は追加開発とする。
初期版に「何でも相談できます」と表示せず、未実装の音声ボタンも置かない。

追加時は会話とメッセージの所有者、保持期間、削除、送信範囲、リクエストID、
意図確認、固定応答型、利用制限、キャンセル・再試行を契約化する。
公開会話APIはCore API、生成は既存AI接続サービスへ配置する。
AIに正本を直接変更させず、保存・適用は既存のユーザー確認経路を維持する。
詳細Schemaは後続チケットで決め、本設計を新APIの実装済み証拠としない。

## 3. 情報設計と画面

主ナビゲーションは「コーチ・目標・設定」の3つ。
コーチを日常の入口とし、参照画面は対話から開く。Goal全体を複数タブに分割する構造にはしない。

| ID | 画面 | 内容・主操作 |
| --- | --- | --- |
| C01 | コーチ | 対象Goal、最新実績、対話、目的、入力欄、参照ボタン |
| C02 | 対象Goal選択 | 所有Goal一覧、新規目標。選択して呼出元へ戻る |
| C03 | 新しい目標の対話 | 自然文、任意補足、期限、計画案の生成 |
| C04 | 計画案の確認・編集 | 最大3指標・3〜5中間目標、編集、確定 |
| C05 | 記録候補の確認 | 今回値、現在→保存後、警告、修正、保存、取消 |
| C06 | 進み具合 | 指標・期間選択、累積推移、目標、元の記録 |
| C07 | 振り返り | 対象期間の記録、固定ガイド、次の操作 |
| C08 | 現行計画・変更案 | 計画、見直し理由、変更前後、適用・取消 |
| C09 | 目標一覧 | Goal選択、新規作成。AI自動順位付けなし |
| C10 | 設定・通知 | 頻度、zone、OS許可状態、ログアウト |
| C11 | 保存済み記録 | 本文、Metric更新、日時。読取りのみ |

C04/C05/C08はフル画面。長い候補を小さなボトムシートだけで確認させない。
C06/C07/C11を閉じると同じGoal・元の対話位置へ戻す。

- ログイン後はC01。最後の選択Goal IDをユーザー別に記憶し、所有権も含め再取得する。
- 未選択・Goalなしなら選択／新規作成を案内。対象決定前の実績入力は非活性。
- 複数Goalの会話を混ぜない。本文・候補がある状態のGoal切替は「続ける／破棄して切替」。
- 通信中のGoal・入力目的変更と別の書込みを止める。参照画面は開ける。
- 戻る操作で未保存の本文を黙って破棄しない。
- 通知はGoalを特定しない既存方式を維持し、ログイン確認→C01→Goal選択→振り返りへ。

## 4. コーチ画面の構造

~~~text
コーチ                                      設定
対象: 今年は12冊本を読む                     変更
読了した本 4 / 12冊                     詳細を見る
──────────────────────────────────────────────
操作ガイド
今日は、何を進めましたか？

あなた
1冊読了。明日は2冊読みたい。

更新候補・未保存
読了した本 +1冊 ／ 現在4冊 → 保存後5冊
予定の2冊は加算していません。
[確認して保存へ] [取り消す]
──────────────────────────────────────────────
[進み具合] [振り返る] [計画]
目的: 記録する                              変更
[今回の実績を書く……]
                                    [候補を作る]
──────────────────────────────────────────────
コーチ                 目標                  設定
~~~

- 対象Goal・最新実績は対話のスクロールに追従させず上部に固定する。
- 指標が複数なら最初の1件＋「ほか2指標」。展開して全指標を確認できる。
  表示順は保存position、最初の指標をGoal全体の達成率と呼ばない。
- 取得中は「実績を取得中」。旧値を残す場合は最終取得日時と未更新表示を添え、
  最新値を確認するまで候補生成・書込みを止める。
- 初期目的は「記録する」。ラベルを常時表示し、実績欄へ直接入力できる。
- キーボード表示時は入力欄をIMEの上へ移動し、下部ナビゲーションを隠す。
- 小画面・大文字・IME時は、サマリーを利用可能高さの25%以内、入力欄を55%以内に制限し、
  各領域内のスクロールで全文と操作へ到達できるようにする。対話表示の領域を残す。
  これは実装時の大文字表示確認に基づく具体化で、通常サイズでは全内容を表示する。
- 対話はLazyColumn。末尾閲覧中だけ応答へ追従。過去を閲覧中なら「新しい応答」ボタン。
- 同じGoalに承認可能な候補は一つ。進捗と再計画を同時に承認可能にしない。

## 5. 発話・カードと保存状態

以下はAndroid内の表示型で、新しいDB Schemaではない。
全項目に対象Goalと操作IDを紐づける。

| 型 | 表示ラベル | 内容 |
| --- | --- | --- |
| UserDraft | あなた・このセッションの入力 | 保存前本文。送信済みでも実績と呼ばない |
| Guide | 操作ガイド | 固定の案内・入力条件・未対応の説明 |
| ProgressCandidate | 更新候補・未保存 | 指標ID、今回値、警告、入力世代、確認・修正へ |
| SavedProgress | 保存済み | 成功応答で確認した保存結果と日時 |
| Advice | AIの助言・取得時点 | summary、next_actions。計画変更の効力なし |
| GoalPlanCandidate | 計画案・未確定 | 新規の計画案。確認・編集へ |
| ReplanCandidate | 変更案・未適用 | 提案ID、基準版、差分、理由 |
| Insight / Review | 保存済み実績から表示 | 取得日時・期間を伴う参照カード |
| OperationError | 候補生成失敗／保存結果未確認 等 | 原因カードに修正・再試行を付ける |

- 数値は構造化応答から描画し、AI本文から抜き出して正本にしない。
- 過去の保存カードは「その時点の結果」。最新値は固定サマリーで示す。
- 初期版はセッション内の会話のみ。再起動時に架空の会話履歴を復元しない。
  代わりに「保存済みの記録を見る」を示す。
- 固定案内をAIの返答と偽らない。「変更しました」等の表現は成功応答後だけ。
- 空白期間からの再開に非難・連続記録の失効・埋め合わせノルマを出さない。

## 6. ユースケース別の操作仕様

### U1/U2: 自然文から計画
1. コーチまたは目標一覧で「新しい目標」。
2. 「何を実現したいですか？」へ本文。初期版はtitleとして上限120文字。
3. 補足は任意のdescription（最大2,000文字）。期限は日付ピッカーで指定する。
4. 入力の要約を確認し「計画案を作る」。成功時は未確定カードを出す。
5. C04で指標名・目標値・単位、中間目標と期限を確認・編集。
6. 「この計画で始める」で確定し、成功後に新GoalのC01へ。

期限や単位を本人の確認なしで確定しない。サーバーの日付検証と端末日付に差が
ある場合は入力エラーとして説明し、勝手に日付を補正しない。
現行confirm APIにはリクエスト単位の冪等キーがない。結果不明の通信断では自動再送せず、
「目標一覧で確認」を提示する。一覧の文字列一致で成功を推測しない。
確定結果照会と安全な再送保証はAPI拡張の課題として残す。

### U3: 対話から記録
1. 対象Goalと「目的: 記録する」を確認して本文入力（最大2,000文字）。
2. 「候補を作る」でprogress/preview。本文送信だけでは保存しない。
3. 今回値とwarningsを「更新候補・未保存」と表示。
4. C05で対象名、今回+値、現在→保存後、単位・目標を確認。手修正・手入力を残す。
5. 「この内容で保存する」を一度押しprogressを実行。二重タップを防ぐ。
6. 成功後にGoalを正本応答で置換。グラフとサマリー更新→「保存しました」→別処理で助言。

- 候補0件も正常な結果として理由を示す。予定・単位違い・曖昧な対象を丸めて加算しない。
- 現行APIは正の更新を1件以上必要とする。「進めなかった」等の本文だけは保存できない。
  制約を伝え、未保存で終了／見直しを選べるようにする。
- 本文・値の編集で旧候補を無効化。古い入力世代への応答は破棄する。
- 保存結果未確認では同じrequest ID・同じpayloadで再試行。
  結果が解決するまでそのpayloadの編集・新IDでの再保存を止める。
- 助言失敗は「記録は保存済み。助言だけ再試行」。記録を再入力させない。

### U4: 進捗の理解
発話なしで「進み具合」→C06。指標・期間→グラフ→元記録C11。
閉じると同じGoal・元の対話位置へ戻る。数値とグラフの仕様は7章。

### U5: 振り返り
- C01からC07へ。7日／30日、実際の日付範囲、表示zoneを明記する。
- 記録件数はProgressLogの件数。増加量は指標別に示し、総合点を作らない。
- 初期版はWeekend 10同様、記録有無に基づく固定の振り返りガイド。
  AIによる期間要約と呼ばない。
- Advisorを利用する場合は「現在の状況へのAI助言」と別表示する。
  現行Advisorは現在Goalと最新履歴を使うため、選択期間だけへの助言と見せない。
- 「記録する」「計画を見直す」でC01の目的を切り替える。

### U6: 計画見直し
1. 「計画」→現行計画→「見直す」、またはC07から見直し目的を選ぶ。
2. 理由を自然文入力（最大2,000文字）してreplan/preview。
3. C08で変更前→後、対象、追加／更新／除外、変更理由を項目ごとに確認する。
4. 「変更案を適用する」と「変更を取り消す」を表示。取消に余分な入力を要求しない。
5. 承認時だけreplan/apply。最終の計画版競合検証はCore API。
6. 成功応答で正本を更新し、参照データ・旧候補を失効させる。

UI取消は候補を操作対象から外すだけ。取消APIはなく、サーバー削除とは表示しない。
409は古い候補／処理済みとして適用を無効化。現行計画の再取得・候補再生成を案内する。
適用応答喪失も結果未確認として再取得する。版の増加だけでは当該提案の適用を証明できない。
履歴保持の既存契約は維持し、UIから過去のMetricやProgressLogを削除しない。

### U7: 再開
最新Goalを再取得して中立の案内を表示。未記録を活動停止と断定しない。
期限超過も事実と選択肢を分け、記録／計画参照を選べるようにする。
前回の未保存発話を保存済み実績として扱わない。

### U8: 通知
- 主ナビゲーション「設定」→通知。発話で通知設定を変更しない。
- 初期無効。端末内・ユーザー別・全Goal共通。毎日／毎週日曜の20時頃を維持。
- zoneは端末zoneを初期候補として選択できるようにし、IANA IDも併記する。
  検索可能な候補選択を設け、任意文字列入力だけを必須にしない。
- アプリ内設定とOS許可・チャンネル状態を別表示。有効化保存時だけ権限を要求。
- 拒否時はOS設定への導線と手動振り返りを残す。再開のたびに要求しない。
- 無効化・ログアウトで予約と表示中通知を取消。省電力等で遅れる可能性を補足する。

## 7. 可視化ページの仕様

### 配置
対象Goal→指標選択→現在値／現在目標／計算可能な率→期間→グラフ→選択点と元記録
→「この期間を振り返る」「記録する」。

### データと計算
- 現行の加算型Metricのみ。Metric IDで対応し、同じ単位でも合算しない。
- 全履歴をinstant昇順・同時刻はログID順に並べ、Decimal相当で累積する。
- 値・単位・日時が有効で履歴合計とcurrent_valueが一致する場合だけ推移・率を表示。
- 達成率=current_value÷現在の正の有限target_value×100。小数1桁。
  期間変更してもこの率は全体の現在値を表すと明記する。
- 7日／30日／全期間。全履歴で整合と累積を計算した後、期間で点を絞る。
  絞った履歴をゼロ起算しない。範囲前の値は「期間開始前の累積」として別表示する。
- 7日／30日は選択zoneで今日を含む暦日。未来・不正日時は期間実績から除外。
  そのため正本との整合が確認できなくなる場合はグラフ・率を表示しない。
- 日付は表示zoneへ変換。軸は月日、点の詳細は年・時刻・zoneまで確認可能。
- 現行APIは記録日時の指定を受け付けない。遡及入力機能があるように見せない。

### グラフ
- 折れ線と記録点。横軸=記録日時、縦軸=累積値（単位）。縦軸は0を含める。
- 上限は表示点と現在目標を収め、値・単位・小数精度を保つ。
- 破線は「現在の目標 12冊」等と直接表示し、過去の目標の推移と呼ばない。
- 線は記録点を結ぶ補助。未記録日への架空のゼロ・記録点・達成予測線を補完しない。
- 同時刻に重なる点も元記録リストで個別に読めるようにする。
- タップした点の日時・累積・今回値を表示。hoverに依存しない。
- 元記録の名前と単位は返却された値を表示。APIにない過去の名前や目標値を復元したと説明しない。
- 表示型は固定。AI生成コードや任意Schemaでグラフを作らない。

| 状態 | 表示 |
| --- | --- |
| 未記録 | 「まだ記録がありません」＋記録入口。架空の0%や線なし |
| 1点 | 点、値、日時、目標のみ。経時傾向を断定しない |
| 期間内記録なし | この期間は記録なし。範囲前累積は別の数値として表示 |
| 目標値なし | 累積のみ。率・目標線なし。現行APIの正目標必須は変えない |
| 履歴不整合 | 正本の現在値と目標値は数値で示し、グラフ・率を隠す。再読込 |
| 再計画後 | 新目標を現在値と併記し、旧参照を失効。全履歴から再計算 |
| 除外Metric | 現行選択に出さない。返却される過去記録は履歴で読める |
| 取得失敗 | 旧表示なら取得日時と未更新表示。推測で補完しない |
| 達成 | 保存済みの成果を認め振り返りへ。未承認の新目標を追加しない |

既存MetricTrendは全期間表示。期間切替・点選択・元記録への遷移は刷新時の追加UI。
再計画の差分や当時の目標を推測してグラフに描かない。

## 8. 状態・競合・エラー

CoachUiStateで対象Goal、目的、入力、候補、処理状態、参照選択を管理する。
処理状態を排他的にし、保存中に編集可能等の矛盾を作らない。

~~~text
Idle → Editing → Generating → Candidate → Confirming → Saving → Saved
                     └→ GenerationError     └→ SaveError / ResultUnknown
Saved → AdviceLoading → AdviceReady / AdviceError
Replan: Reason → Generating → Proposed → Applying → Applied / Stale / ResultUnknown
~~~

- 応答にuserId・goalId・操作ID・入力世代を対応付け、編集・切替・ログアウト後の応答を破棄。
- 参照画面との往復で本文・候補は維持。書込みの多重送信と別目的の書込みを止める。
- 候補生成の待機停止は、応答を画面へ反映しないだけ。サーバー処理や課金の取消は保証しない。
  書込み中に「取消できました」と表示しない。
- 別端末の更新とアプリ再開は正本を再取得する。再計画の最終競合検証を端末へ移さない。
- 401は再認証、403/404はGoal選択。別ユーザーのデータの存在をエラーで明かさない。
- 422は該当入力に修正導線。503/timeoutは失敗した操作だけに再試行。
- 成功応答前の保存済みバッジ・楽観的Metric加算は行わない。
- 生成失敗、保存失敗、結果未確認、助言失敗を分け、同じ「やり直す」で再保存させない。

## 9. 見た目とアクセシビリティ

落ち着いた面と余白、短い案内、読みやすい数字を使う。
派手なアバター・装飾・常時動く演出は置かない。固定ガイドとAI助言を文言で区別する。

| 要素 | 初期トークン・方針 |
| --- | --- |
| 背景 | Light #F5F7F7 / Dark #131C20 |
| カード面 | Light #FFFFFF / Dark #1C282D |
| 本文 | Light #18363D / Dark #E5F3F3 |
| 補足 | Light #52666D / Dark #B2C6CB |
| 主操作 | Light #006B63＋白文字 / Dark #8BD8CE＋#003832文字 |
| 補助面 | Light #DCEEEA / Dark #253E3B |
| 余白 | 4dp基準、8/12/16/24/32dp。左右16〜24dp |
| 角丸 | 入力12dp、カード16dp、ダイアログ24dp |
| 文字 | Material 3 Typography。本文16sp、補足14sp、見出し22〜28sp、数値32sp目安 |
| 操作対象 | 48dp以上。グラフの小さな点にはヒット領域か同等のリスト操作を用意 |

- 状態は文言と形でも示し、色だけで区別しない。期限超過を全面赤で表現しない。
- ボタンは「候補を作る」「この内容で保存する」等、動詞で効果を示す。
- 通常表示はMetricを「測定項目」、Milestoneを「中間目標」とする。
- 320dp・文字200%で主操作を隠さない。チップを折返し、横表を縦の項目カードへ変更。
- 回転・分割画面はViewModelで入力を維持。600dp以上の2ペインはスマートフォン完成後に検討。
- TalkBack読順はGoal→最新値→発話／カード→目的→入力→主操作。
  グラフと同等の数値・記録リストを用意。完了通知で全文を読み直させない。
- 動作低減設定を尊重し、補助的な状態遷移だけにアニメーションを使う。
- Light/Darkと動的配色は実装時に検証。通常文字4.5:1、大きな文字3:1を参考基準とし、
  現時点で画面全体の適合を宣言しない。出典は[案内](README.md)を参照。

## 10. API・責務・一時状態

| UI処理 | 既存API／実装 | 注意 |
| --- | --- | --- |
| Goal選択 | GET /api/v1/goals、GET /api/v1/goals/{id} | 一覧に現在値はない。全Goalを追加取得して総合進捗にしない |
| 初期計画 | POST /api/v1/goals/preview | 本文と期限を揃えて呼ぶ |
| 初期確定 | POST /api/v1/goals/confirm | 冪等キーなし。二重タップ防止と結果不明を分ける |
| 進捗候補 | POST /api/v1/goals/{id}/progress/preview | 解析で保存しない |
| 進捗保存 | POST /api/v1/goals/{id}/progress | 同payload再送でclient_request_idを維持 |
| 助言 | POST /api/v1/goals/{id}/advice | 自由相談・期間専用助言APIではない |
| 再計画案 | POST /api/v1/goals/{id}/replan/preview | サーバーに候補保持。正本は未変更 |
| 再計画適用 | POST /api/v1/goals/{id}/replan/apply | proposal_id、計画版の検証 |
| 可視化・振り返り | Goal詳細＋MetricTrend・ReviewPeriod | 端末の表示用投影。集計API未追加 |
| 通知 | ReviewReminder | 端末内設定とAlarmManager。新規クラウド基盤不要 |

- Composeは表示・イベント、ViewModel＋StateFlowは処理・状態、Repositoryは通信境界。
- CoachScreen、カード群、GoalPicker、TrendScreen、ReviewScreen、PlanReviewScreen、
  NotificationSettingsScreenへ整理する。名前は実装時に調整可能。
- 汎用チャットSDK・独自UIフレームワーク・新サービスを追加する前提にしない。
- AI接続・プロンプト・APIキーは既存Goal Planner / AI接続サービス。
  Android/Core APIへOpenAI SDK等を持ち込まない。
- 正本の保存・認可・最終検証はCore API。表示用を越える共通集計は将来Core APIへ集約する。
- 初期版はAPI・DB・クラウドリソース変更を前提にしない。新APIは実装前に別途契約化する。

### 一時状態と保存範囲
- 選択Goal ID・通知設定はユーザー別端末設定。入力本文・AI応答・カードはViewModelの
  セッション内保持のみ。本文を設定やバックアップへ保存しない。
- 回転は維持する。OSのプロセス終了・強制終了後の未保存本文は復元しない制約を入力導線で伝える。
- プロセス終了後のrequest ID/payload回復も初期版では保証しない。
  再開時は保存記録の確認を案内し、自動再送しない。
  永続outboxを含む完全な再送保証は追加契約の課題。
- ログアウト・ユーザー切替で入力・候補・会話・選択Goalを画面状態から消す。
- 個人本文・認証情報をログや解析イベントへ送らない。計測追加は目的・同意・保持を先に定義する。

## 12. 受け入れテストと評価

[共通S1〜S6](01-principles-and-use-cases.md#4-共通の検証シナリオ)を維持する。
以下は実装時の合格条件であり、現時点で合格済みとは扱わない。

| UC | 合格条件 |
| --- | --- |
| U1/U2 | 自然文・期限から案を作り、編集・確認後だけ保存。未確定が分かる |
| U3 | 読書4/12冊「1冊読了、明日は2冊」→候補+1→確認後5/12。予定を加算しない |
| U3 | 同単位の開発指標をIDで区別。警告、修正、候補取消、超過を扱う |
| U3 | 同ID再送で二重加算なし。助言失敗時に進捗を再保存しない |
| U4 | 利用者が現在値・現在目標・期間を説明でき、未記録を0%と誤認しない |
| U4/U5 | zone境界、期間前累積、同時刻、目標変更、単位不一致を検証 |
| U5 | 固定ガイドと現在状況へのAI助言を区別し、記録にない活動を捏造しない |
| U6 | 全差分と理由を確認。取消・古い提案で正本を変更しない |
| U7 | 21日空白でも非難・埋め合わせを要求せず、記録・計画へ戻れる |
| U8 | Goal未選択でも設定。拒否でも手動利用、無効化・ログアウトで停止 |
| 横断 | 別ユーザー・別Goal・編集前の遅延応答を表示・適用しない |
| 横断 | 相談文のみ保存、自由相談、会話同期が実装済みと誤認させない |

操作目標は、選択済みGoalで1操作以内に入力へフォーカス、一覧から2操作以内。
利用者テストで未保存を保存済みと誤認する件数0、変更適用前の内容説明、
進捗の数値・期間理解を確認する。所要時間・成功率は未測定。

実装時はGradle Wrapperの単体テスト、assembleDebug、lintDebug、Emulatorの一周デモを実施。
API・AI生成を変更した場合は関連Backend検査と読書・アプリ開発・筋トレの回帰評価も実施する。
UI採用と実装完了を区別し、本書とチケットに残件を記載する。

## 13. 残る検証・判断
1. 目的を選んで話す初期版が、利用者の「対話コーチ」への期待を満たすか。
2. 自由相談・永続会話が必要な場合の保持・削除・契約・予算。
3. 新規確定・再計画適用の応答喪失時の結果照会、プロセス終了を跨ぐ再送保証。

5. 固定サマリーとIMEが小画面・大文字設定で入力を圧迫しないか。

これらは構想の再承認待ちではなく、実装・検証で解決する項目。
